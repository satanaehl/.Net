# ComplexNumbers

Учебное консольное приложение с собственной реализацией комплексного
числа. Поддерживает сложение, вычитание, умножение, деление, сопряжение,
модуль, сравнение и форматирование.
Целевая платформа приложения и тестов — **.NET 10** (`net10.0`).

## Сборка и запуск

Команды выполняются в PowerShell из корня репозитория.
Для сборки и приведённых ниже команд нужен .NET 10 SDK.
Приложение использует современный .NET вместо .NET Framework.

```powershell
dotnet restore ComplexNumbers.Tests/ComplexNumbers.Tests.csproj --packages .packages
dotnet build ComplexNumbers.Tests/ComplexNumbers.Tests.csproj --no-restore --configuration Release
dotnet run --project ComplexNumbers/ComplexNumbers.csproj --no-build --configuration Release
```

При первом восстановлении тестовых пакетов нужен доступ к NuGet.org.
Эталонные сборки и targeting pack .NET Framework больше не используются.

## Тесты

Используется [xUnit.net v3](https://www.nuget.org/packages/xunit.v3/4.0.2)
со встроенной поддержкой Microsoft.Testing.Platform для `dotnet test`.
Тестовый проект ссылается на приложение;
доступ к внутреннему классу предоставлен через `InternalsVisibleTo`.

После сборки запустить тесты:

```powershell
dotnet test --project ComplexNumbers.Tests/ComplexNumbers.Tests.csproj --no-build --configuration Release
```

Одиночные сценарии используют `[Fact]`, наборы входных данных —
`[Theory]` и `[InlineData]`. Команда `dotnet test` возвращает ненулевой
код при сбое.

В корневом `global.json` выбраны SDK .NET 10 и Microsoft.Testing.Platform.
SDK допускает более новые исправления и feature bands в пределах .NET 10.

Проверяются арифметика и сохранность операндов, равенство и `null`,
хеширование и поиск в `HashSet`, специальные значения `double`,
форматы вывода и культура. Тесты не зависят от локали компьютера.
Новые операции проверяются на обычных и крайних значениях; эталоном
для конечной арифметики, сопряжения и модуля служит `System.Numerics.Complex`.

## Умножение, сопряжение и модуль

```csharp
var x = new ComplexNumber(2, 3);
var y = new ComplexNumber(4, -1);

Console.WriteLine(x * y);         // 11+i10
Console.WriteLine(x * 2);         // 4+i6
Console.WriteLine(2 * x);         // 4+i6
Console.WriteLine(x.Conjugate()); // 2-i3
Console.WriteLine(new ComplexNumber(3, 4).Magnitude); // 5
```

- Умножение двух чисел использует `(a*c - b*d) + i(a*d + b*c)`.
- Умножение на `double` в любом порядке масштабирует компоненты независимо.
  Например, `(Infinity + i3) * 2` даёт `(Infinity + i6)`. Для `NaN` и
  бесконечностей это может отличаться от `System.Numerics.Complex`, где
  скаляр может участвовать в общей формуле как комплексное число.
- `Conjugate()` возвращает новое число с противоположной мнимой частью.
- `Magnitude` вычисляет длину с масштабированием компонентов, чтобы избежать
  промежуточного переполнения и потери очень маленьких значений.
  Бесконечный компонент даёт положительную бесконечность, в том числе рядом
  с `NaN`; иначе `NaN` распространяется на результат. Если сам результат
  превышает диапазон `double`, возвращается положительная бесконечность.
- Новые операции не изменяют исходные числа. Умножение с `null`
  вызывает `ArgumentNullException`.

## Деление

```csharp
var x = new ComplexNumber(11, 10);
var y = new ComplexNumber(4, -1);
Console.WriteLine(x / y); // 2+i3
Console.WriteLine(x / 2); // 5.5+i5 (разделитель зависит от культуры)
Console.WriteLine(10 / new ComplexNumber(2, 1)); // 4-i2
```

- Поддерживаются комплексное число / комплексное число и деление с `double`
  в обоих порядках. Исходные числа не изменяются, `null` вызывает
  `ArgumentNullException`.
- Нулевой делитель (включая отрицательный ноль) даёт `NaN` в обеих
  компонентах. Исключение `DivideByZeroException` не выбрасывается.
- Используется формула Смита без вычисления суммы квадратов делителя.
  Дополнительное масштабирование уменьшает промежуточное переполнение
  и потерю субнормальных значений. Точность ограничена арифметикой `double`.
- Для входных `NaN` и бесконечностей сохраняется поведение формулы Смита,
  проверенное по `System.Numerics.Complex`. Для крайних конечных значений
  результат может быть лучше стандартной реализации .NET 10: например,
  `(MaxValue + i*MaxValue) / (MaxValue + i*MaxValue)` даёт `1`, а не `NaN`.

Тесты используют как стандартный `Complex`, так и заранее известные
результаты на границах диапазона. Встроенные примеры запуска показывают деление.

## Правила сравнения и вывода

- Числа равны, когда оба компонента равны по `double.Equals`.
  Приближённое сравнение с допуском не выполняется:
  `0.1 + 0.2` и `0.3` могут различаться.
- `NaN` равен `NaN` по этим правилам; бесконечности равны при одинаковом
  знаке. Положительный и отрицательный ноль равны.
- Два `null` равны; число и `null` не равны в любом порядке.
- `Equals`, `==`, `!=` и `GetHashCode` согласованы.
  Компоненты остаются изменяемыми, как в исходном упражнении:
  не меняйте их, пока число используется как ключ словаря или элемент `HashSet`.
- `G` и `A` выводят `2+i3`, `2-i3` либо `2`, если мнимая часть нулевая.
  `P` выводит `(2,3)`. Форматы нечувствительны к регистру.
  Неизвестный формат вызывает `FormatException`.
- Пустой формат означает `G`. Без явной культуры используется текущая
  культура, поэтому десятичный разделитель в демонстрации может отличаться.

## Что исправлено

Проверка `null` в типизированном `Equals` раньше снова вызывала
перегруженный `==`, что приводило к бесконечной рекурсии. Теперь она
использует `ReferenceEquals`. Сравнение компонентов через вычитание и
`Double.Epsilon` заменено на `double.Equals`, добавлен `GetHashCode`.
Убраны закомментированные заготовки и лишние переменные, исправлены
описания действительной и мнимой частей.

## Переход на .NET 10

Основной проект переведён в SDK-style формат, оба проекта используют
`net10.0`. Удалены пакет эталонных сборок .NET Framework и старый
`App.config`, содержавший только настройку запуска Framework 4.5.2.
Правила арифметики, равенства и форматирования сохранены; существующие
тесты проверяют их на новой платформе. Тестовый проект переведён с
NUnit/NUnitLite на xUnit.net с сохранением всех проверяемых сценариев.
