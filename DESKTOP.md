# Два интерфейса на общей логике

Для сборки нужен .NET 10 SDK, для запуска окон — Windows и .NET 10 Desktop Runtime.
WinForms и WPF входят в современный .NET: отдельные NuGet-пакеты этих UI-фреймворков не нужны.
Проекты интерфейсов используют `net10.0-windows`, библиотеки и тесты — `net10.0`.
`global.json` допускает новые SDK feature bands в пределах .NET 10.

## Структура

```text
Capitals.Core ──┬── WindowsFormsCapitals
               ├── WpfCapitals
               └── Capitals.Core.Tests

TextEditor.Core ──┬── WindowsFormsTextEditor
                 ├── WpfTextEditor
                 └── TextEditor.Core.Tests
```

Библиотеки не ссылаются на WinForms, WPF и проекты интерфейсов.
`CapitalsGame` отвечает за вопросы, попытки и победу; `CapitalCatalog` — за чтение пар
страна/столица. Общие данные и тексты локализаций находятся в `Capitals.Core`.
WinForms использует те же `.resx` через ссылки в проекте, WPF — через `QuizText`.
Сохранены исходные файлы Windows-1251 и локализации `be`, `de`, `fr`, `ru` с нейтральной английской.
Каталог встроен в сборку, поэтому запуск не зависит от текущего рабочего каталога.

`TextDocument` отвечает за текст, путь, несохранённые изменения, чтение/запись и решение,
можно ли продолжить после запроса сохранения. Диалоги, меню, выделение, буфер обмена
и Undo остаются в интерфейсах. WinForms сохраняет прежние формы и ресурсы.

WPF-примеры используют XAML и небольшие обработчики событий. MVVM и дополнительные
UI-библиотеки не нужны для текущего размера приложений. Можно добавить Avalonia или
WinUI как ещё один проект, который ссылается на соответствующий `*.Core`.
WPF-кнопки викторины и запрос сохранения редактора имеют английские/русские подписи;
полная локализация нового WPF-интерфейса — отдельная дальнейшая задача.

## Сборка и тесты

PowerShell из корня репозитория:

```powershell
dotnet restore Desktop.slnx --packages .packages
dotnet build Desktop.slnx --no-restore --configuration Release
dotnet test --solution Desktop.slnx --no-build --configuration Release
```

В тестах используется xUnit.net v3 и Microsoft.Testing.Platform.
Случайность и культура задаются явно; файловые тесты создают временные каталоги.
При первом восстановлении пакетов требуется NuGet.org.
GitHub Actions запускает эти проверки на Windows: `.github/workflows/desktop.yml`.

## Запуск

Выбрать одно приложение:

```powershell
dotnet run --project WindowsFormsCapitals/WindowsFormsCapitals.csproj --no-build --configuration Release
dotnet run --project WpfCapitals/WpfCapitals.csproj --no-build --configuration Release
dotnet run --project WindowsFormsTextEditor/WindowsFormsTextEditor.csproj --no-build --configuration Release
dotnet run --project WpfTextEditor/WpfTextEditor.csproj --no-build --configuration Release
```

Викторина: начать игру, ввести столицу по-русски, подтвердить ответ. Для победы нужны
семь правильных ответов, на каждый вопрос отводится пять попыток; вопросы могут повторяться.
Тексты сообщений используют текущую UI-культуру, сравнение ответов — культуру,
выбранную при создании игры (по умолчанию текущую).

Редактор: New/Open/Save/Save As, стандартные операции редактирования и запрос
сохранения перед новым документом, открытием и закрытием. Звёздочка в заголовке
показывает несохранённые изменения.

## Изменения поведения, отдельно от обновления платформы

- Викторина принимает правильный ответ на пятой попытке. Ранее проигрыш проверялся
  до самого ответа; ошибка воспроизведена тестом `CorrectAnswerOnFifthTry_IsAccepted`.
- Пустой ответ считается неправильной попыткой; ответы после окончания игры не меняют состояние.
- Вместо `Troschuetz.Random`/`Thrower` используется стандартный `Random`.
  Вероятностная последовательность изменилась; правила и возможность повторных вопросов сохранены.
  Старый каталог `WindowsFormsCapitals/packages` оставлен как архив, сборка его не использует.
- Отмена сохранения и ошибки файловых операций не сбрасывают признак изменений.
  «Сохранить» использует текущий путь, «Сохранить как» спрашивает новый.
- После успешного сохранения можно продолжить New/Open/Close; открытие тоже проверяет изменения.
- При сохранении не добавляется лишний перевод строки. Новые файлы — UTF-8 без BOM;
  при открытии UTF-8/UTF-16/UTF-32 с BOM кодировка сохраняется. Автоопределения Windows-1251
  в редакторе нет. Сам текст сохраняется без преобразования переводов строк в библиотеке;
  стандартные UI-контролы могут нормализовать их при редактировании.
- Delete в WinForms удаляет выделение, а не весь документ. Форма редактора использует Dock.
- Автоматическая версия сборки `1.0.*` заменена фиксированной `1.0.0.0` для детерминированной сборки.

## Проверка пользовательских сценариев

После изменений UI вручную проверить обе версии:

- Викторина: старт, правильный/неправильный ответ, счётчики, проигрыш, победа, повторный старт.
- Редактор: создание, открытие, сохранение, Save As, отмена обоих диалогов;
  Yes/No/Cancel перед New/Open/Close; недоступный путь, кириллица, Undo и Delete.
- Изменение размера окна и масштабирование; для викторины — все поддерживаемые локализации.

Автоматические тесты библиотек не заменяют проверку настоящих окон.
