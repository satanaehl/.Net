# Работа с репозиторием

## Цель
Постепенно модернизировать учебные C#-проекты, сохраняя их
назначение, небольшой размер и понятность для изучения.

## Подход
- Менять один проект или одну общую задачу за раз.
- Перед изменением изучить код и существующее поведение.
- Отделять обновление платформы от изменения поведения.
- Для исправления ошибки добавлять тест, воспроизводящий её.
- Сохранять корректное поведение; изменения правил описывать явно.
- Выбирать простое решение, соответствующее размеру проекта.
- Добавлять зависимости только при конкретной необходимости.

## Код и тесты
- Отделять вычисления и правила от Console, файлов и WinForms.
- Проверять обычные случаи, границы и ошибочный ввод.
- Делать тесты независимыми от случайности и локали компьютера.
- Файловые тесты выполнять во временных каталогах.
- Не запускать файловые утилиты на личных данных пользователя.
- Сохранять локализации и проверять кодировки ресурсов.
- Не редактировать сгенерированные файлы вручную без необходимости.

## Проверка результата
- Собрать изменённые проекты и выполнить относящиеся к ним тесты.
- Для изменений UI проверить затронутые пользовательские сценарии.
- Обновить README при изменении запуска или поведения.
- В отчёте указать изменения, выполненные проверки и ограничения.
- Не утверждать, что проверка пройдена, если она не выполнялась.
- После подготовки общего решения добавить сюда точные команды
  сборки и тестирования, проверенные в этом репозитории.

## ComplexNumbers

- Приложение и тесты используют .NET 10 (`net10.0`) и SDK-style проекты.
- Консольные MoreLessProgram, FilenameExtension и TreeOfDir обновлять отдельно;
  их целевые версии пока сохранять. Десктопные проекты описаны ниже.
- Для тестов используется xUnit.net v3; запускать через `dotnet test`.
- Равенство компонентов определяется через `double.Equals`, без допуска.
- Приближённое сравнение выполнять отдельно через `ApproximatelyEquals`;
  оно не должно менять точное равенство или хеширование.
- Команды ниже выполняются в PowerShell из корня репозитория:

```powershell
dotnet restore ComplexNumbers.Tests/ComplexNumbers.Tests.csproj --packages .packages
dotnet build ComplexNumbers.Tests/ComplexNumbers.Tests.csproj --no-restore --configuration Release
dotnet test --project ComplexNumbers.Tests/ComplexNumbers.Tests.csproj --no-build --configuration Release
dotnet run --project ComplexNumbers/ComplexNumbers.csproj --no-build --configuration Release
```

- GitHub Actions: `.github/workflows/complex-numbers.yml` собирает и проверяет
  этот проект в Release на Windows. При изменении команд запуска обновлять workflow.
- `global.json` выбирает SDK .NET 10 и Microsoft.Testing.Platform для `dotnet test`.

## Десктопные приложения

- `Desktop.slnx` объединяет викторину и редактор, их библиотеки и тесты.
- `Capitals.Core` и `TextEditor.Core` используют `net10.0`; интерфейсы
  WinForms и WPF — `net10.0-windows`. Библиотеки не должны ссылаться на UI-проекты.
- Правила и состояние добавлять в соответствующую библиотеку, диалоги и контролы — в UI.
- Данные викторины и тексты локализаций принадлежат `Capitals.Core`.
  Исходные `.txt` имеют Windows-1251; не перекодировать их без отдельной проверки.
- Тесты — xUnit.net v3, файловые сценарии только во временных каталогах.
- Проверенные команды из корня репозитория:

```powershell
dotnet restore Desktop.slnx --packages .packages
dotnet build Desktop.slnx --no-restore --configuration Release
dotnet test --solution Desktop.slnx --no-build --configuration Release
```

- Команды запуска и изменения поведения: `DESKTOP.md`.
- CI: `.github/workflows/desktop.yml`; при смене команд обновлять его вместе с документацией.
